# ADR 0024: イベント保存上限は終了済みだけを削る (未実施は消さない)

- **ステータス**: Accepted
- **日付**: 2026-09-17
- **関連**: ADR 0021 (翻訳参考資料の削除連鎖), DESIGN.md 7.1 (ライフサイクル), 8 章 (イベント CRUD)

## コンテキスト

制御 API はイベントを DynamoDB に保存し、`MAX_EVENTS = 1000` 件を超えると
`createEventService.trimOldEvents` が古い分を自動削除していた。この実装に 3 つの問題があった。

1. **まだ実施していないイベントが消える**。削除の除外条件は `status !== "live"` だけで、
   `draft` / `scheduled` / `warmup` はすべて削除候補だった。しかも並び順が `startsAt` の昇順なので、
   「日付を過去にして作った下書き」が真っ先に消える。運用上いちばん失ってはいけないものが
   いちばん先に消える順序になっていた。

2. **消えたことがどこにも出ない**。削除は `create` の副作用として黙って走る。
   さらに `factory.ts` の `cleanupStorage` は `recordings/` `captions/` と翻訳参考資料を
   まとめて消すので、**録画ごと無言で消える**。管理画面には上限の存在すら表示していなかった。

3. **そもそも上限判定が壊れていた**。`DynamoEventRepository.list()` が `LastEvaluatedKey` を
   見ておらず、Query の 1MB 応答上限で結果が打ち切られていた。`slideAssets` / `brandingAssets` を
   持つイベントが増えると 1000 件に届く前に切れるため、`all.length <= MAX_EVENTS` が成立し続けて
   掃除が一切走らない (あるいは誤った範囲を消す) 状態だった。カレンダー表示も部分的な一覧を
   全件のように見せていた。

`MAX_EVENTS = 1000` という数字自体には DESIGN.md にも ADR にも根拠がなく、
「無制限に増えないための保険」として置かれていた。

## 決定

**上限の意味を「合計を 1000 件に抑える」から「終了済みイベントを 1000 件までに片付ける」に変える。**

1. 自動削除の対象は `status === "ended"` のみ。`draft` / `scheduled` / `warmup` / `live` は
   上限を超えても削除しない。結果としてこの上限は**ソフトキャップ**であり、
   未終了イベントだけで 1000 件を超えた場合は超えたまま保持する。
   未実施のイベントが押し出されて消える事故に比べれば、上限超過は害がない。

2. 上限に達したときに作成を拒否する経路は作らない。未終了イベントが 1000 件溜まる状況は
   現実には来ず、拒否は「配信直前にイベントが作れない」という新しい事故を生むだけ。

3. `MAX_EVENTS` の定義は `@stagecast/shared` に置く。管理画面が同じ数字を表示するため、
   制御 API と admin-web で二重管理しない。

4. 管理画面のカレンダー凡例に `保存 N/1000 件` を常時表示し、
   ツールチップに削除条件 (終了済みのみ・古い順・録画も一緒に消える) を書く。

5. 前提条件として `DynamoEventRepository.list()` を全ページ読むよう直す。
   ページングが欠けたままでは件数ベースの保持ポリシー自体が成立しない。

## 影響・トレードオフ

- **良くなる点**: 予定中・準備中のイベントが自動削除で失われなくなる。上限の存在と現在の
  保存件数が管理画面から見えるようになる。一覧が 1MB で切れなくなる。
- **代償**: 未終了イベントが積み上がると 1000 件を超えて増え続ける。`list()` は全件取得のままなので、
  件数に比例して `GET /events` のレイテンシと RCU が増える。実運用で件数が問題になったら、
  一覧 API のページング (または「終了済みは別クエリ」への分割) が次の手。
- **やらなかったこと**: 終了後 N 日で消す年齢ベースの保持。DynamoDB TTL で自然に書けるが、
  TTL 削除は `cleanupStorage` を呼ばないため S3 に録画・字幕が残る。DynamoDB Streams か
  S3 ライフサイクルルールの追加が必要で、CDK 側の作業が増える。件数ベースで足りている間は保留。
- `EventRequestRepository.list()` (`dynamo.ts`) にも同じページング漏れが残っている。
  イベントリクエストは件数が伸びにくいため今回は触っていない。
