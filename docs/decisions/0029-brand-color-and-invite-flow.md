# 0029. 主要アクションを brand 紫にし、招待 URL をロールごと 1 本にする

- ステータス: 採用
- 日付: 2026-09-20
- 関連: ADR 0013 D-4 (Tally Light) / DESIGN.md 4.1 (招待トークン) / `packages/ui/src/tokens.css`
- 後方互換: 招待レコードは **互換あり** (`issuedAtSec` の無い旧レコードは無視して作り直す)

## コンテキスト

管理画面と視聴者向けリクエスト画面の使い勝手を見直した。 調べて分かったこと:

- `Button` の `default` が `tally-500` (オンエア赤) で、主要操作 (イベント作成・保存・承認) と
  「配信中」のシグナルが同じ赤だった。 ADR 0013 D-4 の「赤 = 放送機材のタリー」が薄まっていた。
- ライトテーマの面は無彩色のグレーで、ブランドの手触りが無かった。
- 招待 URL は「発行」ボタンを押すたびに新しいトークンが増え、画面 state にしか無いので
  リロードで消え、また発行する。 期限は発行から 12 時間固定で、前日に発行すると本番で切れていた。
  リポジトリには `listByEvent` まであったが、取り出す API が無かった。
- サイドバーの初期フィルタが「下書き」固定で、予定・配信中のイベントが初見で見えなかった。
- 成果物タブは「一覧を更新」を押すまで空だった。

## 決定

### D-1: brand 紫を導入し、赤をオンエアと破壊的操作に限定する

`tokens.css` に `--brand-*` を足し、`Button.default` / `link` / フォーカスリング / 選択状態を brand に寄せる。
赤 (`tally`) は「配信開始」ボタン (新設の `variant="live"`)・ON AIR 表示・`destructive` だけに残す。

| トークン       | 値        | 用途                                                    |
| -------------- | --------- | ------------------------------------------------------- |
| `--brand-300`  | `#a19edb` | 枠線・チップ (白文字は載せない: 2.5:1)                  |
| `--brand-500`  | `#817dd4` | フォーカスリング・アイコン・アクティブ                  |
| `--brand-600`  | `#6b66c4` | 白文字を載せる塗り (4.86:1)。 `#817dd4` は 3.6:1 で不足 |
| `--brand-700`  | `#5a55ad` | ライトの文字色                                          |
| `--brand-text` | テーマ別  | ダーク `#a19edb` / ライト `#5a55ad`                     |

ライトの面は `#ddddec` 系の薄紫に寄せる (`--surface-2/3/4`)。 機能色 (`success/warning/error/info`) は
白地で文字として 4.5:1 に届かないので、ライトだけ一段濃くする。

両テーマとも塗りは同じ `--brand-600` を使う。 テーマで変わるのは文字色だけ。

### D-2: 招待 URL はロールごと 1 本、期限はイベント終了に追従

- `GET /events/{id}/invites` を追加。 moderator / speaker それぞれ 1 本を返し、無ければその場で作る。
  jti は `${eventId}:${role}` で決定的にする。 同時に 2 回呼ばれても同じレコードに落ちる (作成が冪等)。
- 招待レコードに `issuedAtSec` を持たせ、署名の入力を jti / issuedAtSec / version だけにする。
  **何度取得しても同じ URL 文字列** になり、トークン自体は保存しない。
- 署名内の `exp` は 1 年の天井で、本当の期限は **verify 時に今の `endsAt` で判定**する
  (`endsAt` 未設定なら `startsAt + 2h`、そこに + 1 時間)。 だから `endsAt` を編集しても配った URL は
  そのまま生きて、期限だけ追従する。 期限をトークンに焼き込むと、延長したのに配った URL が本番中に切れる。
- 再発行 (`POST /invites/{jti}/reissue`) は version を繰り上げて旧トークンを `stale-version` にする。
- 失効 (`revoke`) したロールは作り直さず `revoked: true` で返す。 画面は「失効中 / 再発行」を出す。
- admin-web はイベント詳細を開いた時点で取得し、コピーボタンと「再発行」だけを持つ。
  「発行」操作は無くした。 `POST /events/{id}/invites` はテストと fake client のために残す。
- 既定所要時間 2h は `@stagecast/shared` の `DEFAULT_EVENT_DURATION_MS` に一本化 (フォーム・カレンダー・期限が同じ値を見る)。

### D-3: 小さな動線

- サイドバーの初期フィルタを「すべて」にする。
- 成果物タブは開いたら自動で取得する。 失敗は画面全体の赤帯にせず、「一覧を更新」を押したときだけ見せる。

### 却下案

- **ライトだけ紫、ダークは赤のまま**: `Button` の意味がテーマで変わる。 却下。
- **`#817dd4` をそのまま主要ボタンの塗りに**: 白文字で 3.6:1。 本文サイズのラベルに足りない。 却下。
- **トークン文字列を DB に保存して GET で返す**: DB 読み取りが漏れると招待が漏れる。
  署名入力を固定する方が小さい。 却下。

## 影響・トレードオフ

- stage-web の主要ボタンとフォーカスリングも紫になる (packages/ui を共有しているため)。
- `styles.css` の既定ボーダー色を `#e5e7eb` → `var(--line-2)` にしたので、ダークの薄い境界線が少し薄くなる。
- 招待 URL の期限が最長 7 日 (`MAX_TTL_SEC`) を超えうる。 GET / reissue の経路は TTL 検証を通らない。
  イベント単位の署名付き URL なので、露出の範囲はイベント 1 本分に留まる。
- 旧レコード (`issuedAtSec` 無し) は失効しない。 期限切れで自然に死ぬ。
